# Unreleased — 2.0.0


### BREAKING CHANGES

* **api:** `ChaosControlPlane.removeEventListener` and `ChaosActivationHandle.matchedCount()` / `appliedCount()` are new abstract methods; custom implementations must add them.
* **core:** a clock-skew scenario whose policy sets `maxApplications`, `rateLimit`, `activateAfterMatches` or `probability < 1.0` is rejected with `ChaosValidationException`; 1.x ignored those fields for clock skew. `ActivationPolicy.fromJson` takes `activeFrom` and `activeUntil`.
* **instrumentation:** hooks are woven on demand. The agent no longer weaves every hook at start: each interception point belongs to a hook group (`JdkInstrumentationInstaller.HookGroup`) that is retransformed the first time an activated scenario (or an opened session) needs one of its operation types, and stays woven until uninstall. A JVM without scenarios runs unmodified JDK classes; the first activation of a hook group pays its one-time weaving cost, and a weaving failure fails that activation with failure category `INSTRUMENTATION_FAILURE`. The agent argument `instrumentation=eager`, the system property `-Dmacstab.chaos.instrumentation=eager` or the environment variable `MACSTAB_CHAOS_INSTRUMENTATION=eager` restores the 1.x behaviour (every group woven at start).
* **instrumentation:** the premain / agentmain split is gone. Dynamic attach (`agentmain`, still behind its opt-in) and `installForLocalTests()` get exactly the same hook set as `-javaagent:` — sockets, NIO, HTTP, JDBC, clock and the rest are no longer premain-only. `ChaosAgentBootstrap.initialize(agentArgs, instrumentation, environment)` lost its `premainMode` parameter, and `JdkInstrumentationInstaller.install` takes an `eager` flag instead.
* **instrumentation:** the unused handle slot `ADJUST_SCHEDULE_DELAY` (index 5) and `BridgeDelegate.adjustScheduleDelay` were removed. Every `BootstrapDispatcher` handle index above 5 shifted down by one; `HANDLE_COUNT` is now 57.
* **packaging:** the agent JAR (`chaos-agent-bootstrap`) relocates ByteBuddy and Jackson to `com.macstab.chaos.jvm.shaded.*`, so they can no longer clash with the application's own copies (Mockito, Hibernate, Spring). Its published POM declares no dependencies: everything it needs is inside the JAR. The Spring Boot starters no longer depend on `chaos-agent-core` and `chaos-agent-startup-config` at runtime; those classes come from the agent JAR.
* **api:** `chaos-agent-api` no longer depends on `jackson-annotations`. The JSON shape of plans (the `type` discriminators, the `ActivationPolicy` and `NamePattern` creators) is defined by mix-ins in `chaos-agent-startup-config`; serialise and parse plans with `ChaosPlanMapper`, another `ObjectMapper` no longer knows the discriminators.
* the legacy duplicate package tree `com.macstab.chaos.*` (everything outside `com.macstab.chaos.jvm.*`) was removed. Use the `com.macstab.chaos.jvm.*` types.


### Features

* **core:** a dispatch whose operation has no scenario returns before building its `InvocationContext`: 0 B and about 7 ns per intercepted call, down from 104–200 B and 23–54 ns, on every hooked operation (it was only the case for clock reads).
* **instrumentation:** `JdkInstrumentationInstaller.connectDispatcher(runtime)` connects a runtime to `BootstrapDispatcher` without weaving, for benchmarks and tests that drive the dispatch methods directly.
* **build:** `BridgeDispatchBenchmark` measures the woven dispatch path through `BootstrapDispatcher`; a benchmark gate on pull requests into `main` fails a change that makes it more than 15 % and 25 ns slower than `main` (Mann-Whitney U, p < 0.01, same runner; `scripts/jmh-gate.py`). `check` enforces a line and branch coverage floor per module, and CI runs the tests on JDK 21 and 25 on amd64 and arm64.
* **testkit:** `@WithChaos` declares a test's chaos in the plan JSON model, inline or from a class-path resource, as a whole plan or one scenario; repeatable, on classes and methods. Session-scoped scenarios run in the test's session, JVM-scoped ones on the control plane, and both stop with the test (method) or test class. Honoured by the testkit `ChaosAgentExtension` (which then binds the test thread to the session), the Spring Boot 3/4 test extensions (new `beforeEach`/`afterEach` for method-level annotations), `ChaosMicronautExtension` and `ChaosQuarkusExtension`. `WithChaosSupport` is the shared, public implementation.
* **testkit:** `ChaosAssertions` — `assertThat(handle).applied().atLeast(n)`, `exactly`, `atMost`, `never`, `within(Duration)` for effects on other threads, `matched()`, `hasState`, and on diagnostics `hasNoFailures()`, `hasNoFailuresFor(ids...)` and `scenario(id)`; failures are opentest4j `AssertionFailedError`.
* **api:** `ActivationPolicy` gains an absolute wall-clock window, `activeFrom` and `activeUntil` (JSON: ISO-8601 instants), read from the real system clock so an injected clock skew cannot move it; the equivalent of the native library's `@from`/`@until`. New factories `ActivationPolicy.count(n)` (`@first=N`) and `ActivationPolicy.window(from, until)`, and builder methods `activeFrom`, `activeUntil` and `window`. The 8-argument constructor is kept.
* **api:** DNS answer effects: the new `DNS_ANSWER` operation (when `InetAddress.getAllByName` returns or fails) with `dnsAnswer` — override with IP literals even when the lookup failed (`OVERRIDE`), keep one address family (`FILTER_FAMILY`), shuffle (`SHUFFLE`), limit (`LIMIT`) — and `dnsRewrite(host)` on `DNS_RESOLVE`, which resolves another name (`REWRITE`).
* **instrumentation:** file coverage beyond streams: `RandomAccessFile` and `FileChannel` reads and writes are `FILE_IO_READ` / `FILE_IO_WRITE` events with their path and byte count, and fsync (`FileChannel.force`, `FileDescriptor.sync`) is the new `FILE_IO_SYNC`, failing with `SyncFailedException`. `ChaosEffect.tornWrite()` makes a `FileChannel` write succeed short (`TORN`). `RandomAccessFile` reads of `.jar` / `.zip` / `.jmod` archives are never evaluated: they are class loading.
* **api:** data-delivery effects, the native library's network effects on the real socket and file calls: `trickle(maxBytes)` caps each socket read (`TRICKLE`), `corruptRead()` flips one bit of the bytes a socket or file read returned (`CORRUPT`), `timeout()` waits out the socket's own `SO_TIMEOUT` or connect timeout and throws `SocketTimeoutException`, never firing on an infinite timeout (`TIMEOUT`), and `connectionReset()` closes with `SO_LINGER` 0 so the peer sees a reset (`RESET`).
* **api:** `ChaosEffect.errno(Errno)` — the native library's `ERRNO` effect as typed Java exceptions: network errors (`ECONNREFUSED`, `ETIMEDOUT`, `ECONNRESET`, `EHOSTUNREACH`, `ENETUNREACH`, `EPIPE`, `EADDRINUSE`) become the matching `java.net` exceptions; file errors (`ENOSPC`, `EDQUOT`, `EROFS`, `EACCES`, `ENOENT`, `EIO`, `EMFILE`) become `FileSystemException` subclasses carrying the file's path and the system's reason text.
* **api:** `ClockSkewMode.REGRESS` — the clock steps back once by `skewAmount` and stays shifted (the first read in the window arms it, the next one jumps), the native library's `REGRESS`.
* **instrumentation:** client-library hooks with their own operations and selectors: Kafka (`MESSAGE_SEND` / `MESSAGE_RECEIVE`, `messaging` selector by topic), gRPC (`RPC_CALL`, `rpc` by full method name), Jedis and Lettuce (`REDIS_COMMAND`, `redis` by command), R2DBC (`R2DBC_STATEMENT_EXECUTE` in the `jdbc` selector), the AWS SDK for Java v2 (`AWS_SDK_CALL`, `awsSdk` by service and operation) and Netty (`NETTY_CHANNEL_WRITE` / `NETTY_CHANNEL_READ`, `netty` by peer, including the native transports). A reject throws the library's own exception type. The libraries are matched by name; none is a dependency of the agent.
* **instrumentation:** `java.net.HttpURLConnection` and `HttpsURLConnection` requests are `HTTP_CLIENT_SEND` events (once per request, however the connection is driven), which covers Spring's `RestTemplate` default transport and the AWS SDK URL-connection client. A suppressed request fails with `java.net.ConnectException`.
* **instrumentation:** `MethodSelector` scenarios weave themselves. Activating one weaves entry and exit hooks into every concrete method its class and method patterns name (loaded classes are retransformed, later ones woven at load); removing it restores the original bytecode. One transformer covers all registered method selectors, so overlapping selectors weave a method once. `signaturePattern` now works: it is matched against the JVM method descriptor. The manual hooks remain for use without the agent.
* **api:** call-context filters, the equivalents of the native library's address, path and `@size` qualifiers. `NetworkSelector` gains `remoteCidr` (IPv4/IPv6 CIDR, parsed without DNS), `remotePort`, `minBytes` and `maxBytes`; `FileIoSelector` gains `pathPattern` (`PathPattern.under(dir)`, `/`-boundary prefix on the lexically normalised path), `minBytes` and `maxBytes`. Socket reads now report the bytes requested and every socket operation reports the peer port; file reads and writes report their path and byte count. The previous constructors are kept.
* **core:** clock-skew scenarios honour `activeFor`, `activeFrom` and `activeUntil`, and stressors end at `activeUntil`.
* **diagnostics:** `ChaosDiagnostics.snapshot().runtimeDetails()` contains `wovenHookGroups` — the comma-separated, sorted names of the hook groups woven so far (empty when none).


* **observability:** status and hits files in the native library's format (`<tmpdir>/.chaos-jvm.status` after every load and reload, with `line`/`column`/`reason` for a rejected plan; `<tmpdir>/.chaos-jvm.hits.<pid>` with each scenario's applied count), switchable with `reports=off` and relocatable with `reportsDir`.
* **events:** `REGISTERED`, `SKIPPED` (with the policy check as `reason`, published while a listener is registered) and `FAILED` (activation failures with their `category`) are now published; `ChaosEventListener.async(listener)` delivers on an agent-owned thread through a bounded queue (`droppedEvents` in the diagnostics); `ChaosControlPlane.removeEventListener`.
* **observability:** `ChaosActivationHandle.matchedCount()` / `appliedCount()`; the MBean gains `listScenarios`, and — behind the opt-in `jmxControl=true` — `activatePlan(json)`, `stopScenario(id)` and `stopAll()`; new optional module `chaos-agent-micrometer` (`ChaosMeterBinder`).

* **startup-config:** reload robustness: changes are detected by the resolved file, modification time, size, file key and a SHA-256 of the contents (a touch reloads nothing; a rewrite in the same timestamp tick is caught by re-reading provisional reads made within 20 ms of the modification); broken contents keep the current plan and are parsed once; a removed config file stops its scenarios and removes the status file; Kubernetes ConfigMap and Secret mounts (`<name>` → `..data/<name>`) are followed, every other symbolic link is still rejected.

* **sessions:** a session now follows work handed off from a bound thread to `ForkJoinPool` tasks (submissions and forks — `CompletableFuture.*Async`, parallel streams), threads started with `Thread.start()` and virtual threads (`newVirtualThreadPerTaskExecutor` too), not only executor submissions.

### Performance Improvements

* **core:** `ScenarioRegistry` keeps an immutable index from operation type to controllers, pre-sorted by descending precedence then id and swapped on register/unregister. `match()` evaluates only the scenarios whose selector names the intercepted operation and no longer sorts per call; clock-skew reads use the same index and return immediately when no scenario names the clock.
* **instrumentation:** the dispatch path allocates nothing per call. `BootstrapDispatcher` no longer routes through the shared `invoke(ThrowingSupplier, fallback)` trampoline (whose call site saw every lambda, so the JIT could not elide the 24-byte capturing lambda allocated per intercepted call); each dispatch method guards reentrancy inline. `ThrowingSupplier` was removed from the bootstrap bridge.
* **api:** `NamePattern` GLOB matching uses an allocation-free wildcard matcher instead of the compiled regex for ordinary candidates, with identical results (candidates containing line terminators or surrogate characters still use the regex).
